# 用 iOS 捷徑快速記一筆（LINE Pay 付款通知）

> 對應 issue：[#1488](https://github.com/redtear1115/oikos/issues/1488)。程式入口：`lib/quickAdd.ts`（解析）、`app/(dashboard)/_components/QuickAddProvider.tsx`（交付）。

捷徑做的事只有一件：**打開 Futari，讓「記一筆」帶著金額、分類、描述跳出來**。確認、改分類、按儲存仍然由你自己來——捷徑不會在背景寫入任何紀錄（背景寫入是之後的版本）。

---

## 網址格式

### App（iOS／Android 殼）

```
dev.southernlight.futari://add?amount=<金額>&category=<分類>&note=<描述>
```

### 網頁／加到主畫面的 PWA

```
https://futari.southern-light.dev/dashboard#add=expense&amount=<金額>&category=<分類>&note=<描述>
```

網頁版用 `#` 後面的片段帶值：片段不會送到伺服器，也不會出現在伺服器紀錄或分析資料裡；Futari 讀完就把它從網址列拿掉，重新整理或按返回不會再跳一次。

### 參數

三個參數都可以省略；某個值不合格時只有那一格不帶入，其他照樣帶入。

| 參數 | 規則 | 不合格時 |
|---|---|---|
| `amount` | 正整數，1～9,999,999。可以有千分位逗號（`1,200`），全形數字（`１２０`）也可以。小數、負數、`1e5` 這類寫法都不收 | 金額空白，自己輸入 |
| `category` | 下表其中一個 id，大小寫要完全一樣 | 用預設的「飲食」 |
| `note` | 會變成「描述」。最多 100 個字，控制字元與改變文字方向的隱形字元會被拿掉 | 描述空白，儲存前要自己填 |

分類 id：

| id | 顯示 |
|---|---|
| `dining` | 飲食 |
| `clothing` | 服飾 |
| `housing` | 居住 |
| `transit` | 交通 |
| `education` | 教育 |
| `entertainment` | 娛樂 |
| `health` | 醫療 |
| `financial` | 金融 |
| `other` | 其他 |

網址只能帶上面三個值。日期（今天）、誰付的（你）、分攤方式（你的預設）、幣別（帳本主幣別）都照「記一筆」平常的預設，網址裡寫了也不會採用。今天剛好在旅行期間時，也**不會**自動歸到那趟旅行——LINE Pay 的金額是台幣，要歸到旅行請在畫面上自己選。

例：

```
dev.southernlight.futari://add?amount=120&category=dining&note=LINE%20Pay%20%E5%8D%88%E9%A4%90
```

### 什麼時候不會跳出來

- **另一個視窗正開著**（例如正在改某一筆）：捷徑會被忽略，畫面和你改到一半的內容都不動。關掉視窗後再跑一次捷徑。
- **正在看過去的章節**：過去章節是唯讀的，不會跳出來。先切回目前的章節。
- **還沒登入**：登入後會停在首頁，不會帶入金額，要再跑一次捷徑。

## 捷徑設定步驟（以 LINE Pay 付款通知為例）

前提：iPhone 已安裝 Futari App 並登入。下面是在既有的「linepay 記帳」自動化上，把最後一步改成打開 Futari。

1. 打開「捷徑」App →「自動化」→ 點既有的「linepay 記帳」（或按「＋」新增一個）。
2. **觸發條件**維持原樣：
   - App：LINE
   - 名稱包含「LINE錢包」
   - 訊息包含「付款完成」
   - 建議選「立即執行」，不然每次都要先點一下通知橫幅。
3. **解析金額**維持原樣：用裝置端模型從通知內文取出付款金額，**只輸出數字**（例如 `120`，不要帶「元」或「NT$」）。把這個結果的變數命名為「金額」。
4. （可選）**準備描述**：
   1. 加一個「文字」動作，內容例如 `LINE Pay`，或從通知內文取出的店家名稱。
   2. 加一個「URL 編碼」動作，輸入選上一步的文字。把結果命名為「描述」。
   中文和空白一定要先經過「URL 編碼」，不然網址會斷在中間，描述會是空的。
5. 加一個「文字」動作，內容輸入（把 `[金額]`、`[描述]` 換成上面的變數）：
   ```
   dev.southernlight.futari://add?amount=[金額]&category=dining&note=[描述]
   ```
   沒做第 4 步就把 `&note=[描述]` 整段拿掉。分類想換成別的，就改 `category=` 後面的 id（見上表）。
6. 加一個「打開 URL」動作，輸入選第 5 步的文字。
7. 原本「記錄支出 [金額] 元於餐飲」那一步刪掉——現在由 Futari 記。
8. 測試：在捷徑編輯畫面按右下角 ▶︎ 執行，Futari 應該打開並跳出「記一筆」，金額和分類已經填好。確認後按「儲存」。

### 沒有裝 App、用網頁版的人

第 5 步改用網頁網址，第 6 步一樣用「打開 URL」：

```
https://futari.southern-light.dev/dashboard#add=expense&amount=[金額]&category=dining&note=[描述]
```

會在 Safari 打開。要先在 Safari 登入過 Futari。

## 常見狀況

| 狀況 | 原因／處理 |
|---|---|
| Futari 打開了，但沒有跳出「記一筆」 | 有視窗開著、正在看過去章節，或還沒登入（見上面「什麼時候不會跳出來」） |
| 跳出來了，金額是空的 | 第 3 步的輸出不是純數字（例如帶了「元」、小數點或空白以外的字）。讓模型「只輸出數字」 |
| 描述是空的或只有一半 | 第 4 步沒做「URL 編碼」 |
| 分類是「飲食」而不是我寫的 | `category` 的 id 拼錯或大小寫不同 |
| 同一筆跑了兩次捷徑，跳了兩次 | 預期行為：兩筆金額一樣的付款是可能的，所以每跑一次就跳一次。不想記的那次按「取消」就好 |
