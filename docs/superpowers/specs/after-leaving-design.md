# 離開之後：舊章節與留下的人事物

> 有人離開帳本之後，那段關係留下的紀錄、人、還會動的東西，各自變成什麼。
> 橫切三條離開路徑：自願離開（`leaveGroup`）、被移除（`removePartner`）、刪除帳號（`process_account_deletions`）。

---

## 產品立場

> **章節屬於那段關係，不屬於任何一方。翻頁之後，章節封存——看得到、改不了、不再長大。**
> **事留下，人停在當時，會動的東西停下。**

這延續 [epoch-readonly](epoch-readonly-design.md) 的「故事已經翻頁了 別糾結了 記錯就記錯 記錯也是一種回憶」：回憶不修改，也不刪減。

在這份 spec 之前，三條離開路徑對舊回憶各有一套做法，沒有共同的說法：自願離開把章節拆成兩半、被移除的人完全進不去、刪除帳號把人匿名化但紀錄完整留下。這份 spec 定下共同的立場，三條路徑都以它為準。

### 事（紀錄）：留下、完整、封存

- 已關閉的章節保有那段期間兩個人的全部紀錄：支出、進帳、結算、月回顧留言。
- 誰都不帶走一半，誰都不撕掉。離開不是分家產。
- 章節唯讀（epoch-readonly），離開不會讓任何一方取得修改或刪除舊章節的權力。
- 紀錄的消失只能是使用者明確要求的結果（刪除帳號移除的是個資，不是共同的紀錄），不能是離開流程的副作用。

### 人：停在當時

- 舊章節裡的對方，以「那段時間的那個人」出現：章節關閉時的名字，不顯示頭像，不隨對方之後改名、換頭像而更新。
- 舊章節不連到任何人「現在」的樣子：看不到對方現在的名字頭像、新伴侶、目前的餘額、待確認卡、之後才出現的愛物。反過來，對方回看時也看不到你的現在。
- 這是對兩邊的保護，不是懲罰：留下的人不必看見對方的新生活，離開的人也一樣。
- **刪除帳號是例外**：個資要真的移除，所以在所有章節一律顯示「已離開的夥伴」（見 [account-deletion](account-deletion-design.md)）。
- 舊章節以外的地方另當別論：目前帳本裡仍指向前伴侶的長存物件（愛物、保單、定期規則）屬於「現在」，用「前伴侶」與重新選擇的提示（#1486 / #1579 / #1588 / #1589），不在本節範圍。

### 會動的東西：停下，不追著人跑

- 會在未來產生新事件的東西，在離開的那一刻停住：
  - 離開者的定期規則暫停，未處理的待確認卡清掉（#1588）。已寫入的紀錄、已略過或已確認的卡片不動。
  - 推播不再送給已經不在帳本的人（#1605）。
  - 未接受的邀請作廢。
- 長存物件（房、車、保單）是「物」不是「事」，照既有規則跟著主人走（`leaveGroup` 依 owner；跨帳本的引用指向凍結副本，#1442）。

### 誰能回看

| 離開方式 | 留下的人 | 離開的人 |
|---|---|---|
| 自願離開 | 唯讀回看完整章節 | 唯讀回看他待過的章節 |
| 被移除 | 唯讀回看完整章節 | 唯讀回看他待過的章節 |
| 刪除帳號 | 唯讀回看完整章節，對方顯示「已離開的夥伴」 | 人已不在 |

- 被移除的人跟自願離開的人一樣能回看（2026-10-08 決策）：那段時間也是他的回憶，不因為是被動離開就收回。
- 回看的範圍只有那段章節。進入的是「當時」，不是對方的現在（見上節「人：停在當時」）。

## 不做

- ❌ 「隨時間淡去」的視覺效果（褪色、模糊濾鏡）。模糊用在人與現在的連結上，不用在事上；讓畫面替使用者決定「此刻該感傷」，是品牌準則說的矯情。
- ❌ 離開後修改或刪除舊章節的入口，包括「把我付的那幾筆帶走」。
- ❌ 因為離開而把舊章節的餘額變成可結算的債。舊章節的餘額是已封存的歷史，不是待處理的數字（PRODUCT.md：do not surface a number the user cannot act on）。

## Acceptance criteria

- 任何一條離開路徑之後，留下的人在舊章節看到的紀錄筆數，與離開前在那段章節看到的相同。
- 離開的人（自願或被移除）能從「過去的時光」進入他待過的章節，唯讀，不會被導去登入頁。
- 舊章節的任何畫面，都不出現任何人現在的頭像、之後改過的名字、新伴侶、目前餘額或待確認卡。
- 離開或被移除之後，那個人不再收到原帳本的任何推播。
- 刪除帳號之後，對方在所有章節顯示「已離開的夥伴」。
